# Technical Architecture Document (TAD)

## 1. Executive Summary
Design a highly secure, customer-facing web application on **Azure Kubernetes Service (AKS)** in **East US** with:
- **10,000 requests per minute** expected load
- **Auto-scaling** for pods and nodes
- **99.99% uptime target** in a single region
- **PCI-DSS-aligned encryption and secret handling**
- **No public IPs on AKS nodes**
- **Ingress only through Application Gateway WAF v2**
- **All PaaS dependencies reachable only through Private Endpoints**

This architecture uses a **hub-and-spoke network pattern** with a dedicated application spoke for AKS and private service access, while keeping the public surface area limited to Application Gateway WAF v2.

## 2. Scope
### In scope
- Customer-facing web application on AKS
- Application Gateway WAF v2 ingress
- AKS nodes without public IPs
- Azure Cache for Redis Premium
- Azure Database for MySQL Flexible Server
- Azure Container Registry
- Azure Key Vault
- Private Endpoint-only access for all listed PaaS services
- PCI-DSS-aligned encryption and access controls

### Out of scope
- Exact subnet sizing and IP plan
- VM SKU selection and node pool sizing
- Application code implementation
- Detailed Terraform/Bicep implementation

## 3. Architecture Overview
### Core design principles
1. **Zero Trust by default**
   - No public access to PaaS data services
   - No implicit trust between workloads
2. **Least privilege everywhere**
   - Managed identities preferred over secrets
   - Narrowly scoped role assignments
3. **Private-by-design**
   - Private Endpoints for all required PaaS services
   - Private DNS resolution mandatory
4. **Defense in depth**
   - WAF, network isolation, identity controls, encryption, and logging
5. **Auditability**
   - Security-relevant actions logged centrally and retained per policy

## 4. Logical Architecture
### User entry path
1. Customer connects to the public endpoint of **Application Gateway WAF v2**
2. WAF inspects and forwards allowed traffic
3. Application Gateway routes traffic to **AKS ingress**
4. AKS services process the request
5. Application services access:
   - **Redis** via Private Endpoint
   - **MySQL** via Private Endpoint
   - **Key Vault** via Private Endpoint
   - **ACR** via Private Endpoint for image pulls

### Application pattern
Use a **modular microservices architecture** with a **Web-API + async worker** pattern:
- **Web tier**: stateless API services running in AKS
- **Async processing tier**: background workers for non-blocking tasks
- **CQRS-lite** where it helps
- **Transactional Outbox** for reliable event publication

### Suggested bounded contexts
- Identity/Profile Service
- Catalog/Content Service
- Order/Transaction Service
- Payment Orchestration Service
- Notification Service
- Audit/Compliance Service
- Admin/Backoffice API

## 5. Network Architecture
### Topology
Use a **hub-and-spoke VNet topology**:
- **Hub VNet** for shared security and admin services
- **Application Spoke VNet** for AKS, Application Gateway, and private endpoints

### Key subnets
- **AppGatewaySubnet**: Application Gateway WAF v2
- **AKS-Subnet**: AKS node pools, no public IPs
- **PrivateEndpoint-Subnet**: Private Endpoints for ACR, Key Vault, Redis, MySQL
- Optional **Management-Subnet**: jump/ops tooling if required

### Network controls
- NSGs on all subnets
- UDRs if egress control is required
- Deny-by-default inbound posture
- Restrict AKS egress to required Azure services and private IPs only

### Private DNS zones
Create and link the following zones to the application VNet:
- `privatelink.azurecr.io`
- `privatelink.vaultcore.azure.net`
- `privatelink.redis.cache.windows.net`
- `privatelink.mysql.database.azure.com`

## 6. Security Architecture
### Public network access
Must be **disabled** for:
- Azure Container Registry
- Azure Key Vault
- Azure Cache for Redis Premium
- Azure Database for MySQL Flexible Server

### Identity and access
- Use **Entra ID** for administrators
- Enforce **MFA** and **PIM** for privileged access
- Use **managed identities** for AKS and workload access
- Prefer **Azure Workload Identity** for pod-to-Azure authentication
- Restrict Kubernetes RBAC to least privilege

### Ingress security
- **Application Gateway WAF v2** is the only public entry point
- WAF in **Prevention** mode
- Enforce **HTTPS only** and **TLS 1.2+**
- Use OWASP managed rules and custom rules as needed

### Secrets and certificates
- Store secrets, certificates, and keys in **Key Vault**
- No secrets in code, images, or CI logs
- Rotate secrets and certificates regularly
- Enable soft delete and purge protection in Key Vault

## 7. Data Architecture
### Azure Cache for Redis Premium
**Purpose**
- Session state
- Response caching
- Distributed locks
- Short-lived tokens and throttling counters

**Controls**
- Private Endpoint only
- Public network access disabled
- TLS enforced in transit
- Use only transient or derived data

### Azure Database for MySQL Flexible Server
**Purpose**
- System of record for transactional application data

**Controls**
- Private access only
- Public network access disabled
- TLS 1.2+ for all client connections
- Least-privilege DB accounts per service
- Automated backups and point-in-time restore enabled

### Azure Container Registry
**Purpose**
- Store and distribute container images

**Controls**
- Private Endpoint only
- Public network access disabled
- Access restricted to AKS and approved build identities

### Azure Key Vault
**Purpose**
- TLS certificates
- DB credentials
- App secrets
- Encryption keys

**Controls**
- Private Endpoint only
- Public network access disabled
- Soft delete and purge protection enabled
- Access restricted to workload and admin identities

## 8. Availability and Resilience
### Availability target
- **99.99% in East US** as a service objective
- Single-region design with zone-aware components where supported

### Resilience measures
- Application Gateway WAF v2 deployed zone-redundant if available
- AKS node pools spread across availability zones
- Multiple replicas for all application pods
- Pod anti-affinity and topology spread constraints
- Pod Disruption Budgets
- Cluster Autoscaler and HPA
- Redis Premium with replication/failover capabilities
- MySQL Flexible Server with HA/zone redundancy where supported

### Resilience patterns
- Stateless services
- Timeouts, retries with jitter, and circuit breakers
- Bulkheads to isolate failures
- Idempotency keys for write APIs
- Graceful shutdown and connection draining

## 9. Scaling Design
### Traffic profile
- 10,000 requests/minute ≈ 167 requests/second average
- Design for burst capacity above average

### Scaling approach
- **HPA** for application pods
- **Cluster Autoscaler** for node pools
- Optional **KEDA** for event-driven workloads
- Redis for cache and session offload
- MySQL connection pooling to protect the database

## 10. Compliance and Governance
### PCI-DSS-aligned controls
- TLS 1.2+ in transit
- Encryption at rest
- Least privilege access
- Centralized logging and monitoring
- Secure configuration baselines
- Change control and approval workflow
- Regular access reviews

### Governance guardrails
- Azure Policy to deny:
  - public network access on approved PaaS services
  - public IP assignment to AKS nodes
  - noncompliant TLS settings
  - missing diagnostic settings
- Policy-as-code in CI/CD for identity, network, diagnostics, and private endpoint requirements
- Security review for changes affecting ingress, identity, encryption, DNS, or private connectivity

## 11. Logging and Monitoring
### Mandatory log sources
- Application Gateway WAF logs
- AKS control plane logs
- AKS audit logs
- Container and application logs
- Key Vault diagnostic logs
- ACR audit/access logs
- Redis diagnostic logs
- MySQL audit/security logs where available
- Entra ID sign-in and audit logs
- Azure Activity Logs
- Network flow/security logs where applicable

### Centralization and alerting
- Send all security-relevant logs to a centralized SIEM/SOC platform
- Alert on:
  - public network access changes
  - Private Endpoint/DNS failures
  - WAF blocks and anomalies
  - privilege escalation
  - secret access anomalies
  - failed authentication spikes
  - database access anomalies
  - registry image pull anomalies

## 12. Recommended Azure Service Set
- Azure Kubernetes Service (AKS)
- Application Gateway WAF v2
- Azure Cache for Redis Premium
- Azure Database for MySQL Flexible Server
- Azure Key Vault
- Azure Container Registry
- Azure Private Link / Private Endpoints
- Azure Private DNS Zones
- Azure Monitor / Log Analytics
- Microsoft Defender for Cloud
- Azure Policy

## 13. Final Recommendation
This is the best-fit Azure architecture for the stated requirements:
- Public ingress via **Application Gateway WAF v2** only
- **Private AKS** with no public IPs on nodes
- **Private Endpoint-only** access to ACR, Key Vault, Redis, and MySQL
- **Managed identities** and **workload identity** for authentication
- **TLS everywhere** and PCI-DSS-aligned encryption
- **Centralized logging and alerting**
- **Autoscaling** for both pods and nodes
- **Single-region residual availability risk** formally accepted for the 99.99% target
