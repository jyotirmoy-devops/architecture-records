## 1. Executive Summary
Design a highly secure, customer-facing web application on Azure Kubernetes Service (AKS) in East US with 10,000 requests per minute, autoscaling, 99.99% single-region availability, PCI-DSS-aligned encryption, no public IPs on AKS nodes, Application Gateway WAF v2 as the only public ingress, and private-only connectivity for all PaaS services.

## 2. Business and Technical Requirements
- Customer-facing web application
- Platform: Azure Kubernetes Service (AKS)
- Traffic: 10,000 requests per minute
- Auto-scaling required
- Availability target: 99.99% in a single region
- Region: East US
- Compliance: PCI-DSS encryption standards
- Ingress: Application Gateway WAF v2
- AKS nodes must not have public IPs
- Data services: Azure Cache for Redis Premium and Azure Database for MySQL Flexible Server
- Security constraint: all PaaS services (ACR, Key Vault, Redis, MySQL) must have public network access disabled and use Private Endpoints only

## 3. Target Architecture Overview
The solution uses a hub-and-spoke network topology with a dedicated application spoke and centralized security controls.

### 3.1 Public Edge
- Internet users connect only to Application Gateway WAF v2.
- WAF inspects and forwards HTTPS traffic to AKS ingress.
- WAF policy should be tuned and run in prevention mode after validation.

### 3.2 Application Layer
- AKS runs as a private cluster.
- AKS nodes have no public IPs.
- System and user node pools are spread across availability zones where supported.
- Horizontal Pod Autoscaler and Cluster Autoscaler are enabled.

### 3.3 Data and Platform Services
- Azure Cache for Redis Premium: private endpoint only, public access disabled.
- Azure Database for MySQL Flexible Server: private endpoint only, public access disabled.
- Azure Container Registry: private endpoint only, public access disabled.
- Azure Key Vault: private endpoint only, public access disabled.

### 3.4 Security and Egress
- Azure Firewall provides controlled outbound access.
- Private DNS zones resolve private endpoint FQDNs.
- Log Analytics centralizes diagnostics and audit logs.

## 4. Logical Architecture
### 4.1 Request Flow
1. Customer sends HTTPS request to Application Gateway WAF v2.
2. WAF evaluates the request and forwards it to AKS ingress.
3. AKS routes traffic to application pods.
4. Application pods use Redis for caching/session acceleration.
5. Application pods use MySQL Flexible Server for transactional persistence.
6. Application pods retrieve secrets and certificates from Key Vault.
7. AKS pulls container images from ACR.
8. Outbound traffic is filtered through Azure Firewall.

### 4.2 Application Pattern
- Stateless web/API workloads in AKS
- Cache-aside pattern with Redis
- MySQL as the system of record
- Managed identity-first authentication
- Secrets externalized to Key Vault

## 5. Network Design
### 5.1 Hub VNet
- Azure Firewall
- Optional Bastion for administrative access
- Shared DNS forwarding if required

### 5.2 Application Spoke VNet
- Application Gateway subnet
- AKS subnet(s)
- Private Endpoint subnet
- Private DNS zone links

### 5.3 Private DNS Zones
- privatelink.azurecr.io
- privatelink.vaultcore.azure.net
- privatelink.redis.cache.windows.net
- privatelink.mysql.database.azure.com

### 5.4 Routing and Segmentation
- UDRs from AKS subnet to Azure Firewall for controlled egress
- NSGs applied to AKS and private endpoint subnets
- Deny all by default, allow only required flows

## 6. Compute and Scaling Design
### 6.1 AKS Configuration
- Private AKS cluster
- Managed identity for cluster operations
- No public node IPs
- Azure CNI or equivalent enterprise networking model

### 6.2 Node Pools
- System node pool: minimum 3 nodes, zone spread
- User node pool: minimum 3 nodes, autoscaler enabled, zone spread

### 6.3 Autoscaling
- Horizontal Pod Autoscaler based on CPU, memory, and custom metrics if needed
- Cluster Autoscaler on user node pool
- Optional KEDA for event-driven workloads

## 7. Security Architecture
### 7.1 Identity and Access
- Microsoft Entra ID for human access
- MFA and PIM for privileged users
- Managed identities for AKS and workloads
- Azure RBAC and Kubernetes RBAC mapped to Entra groups

### 7.2 Secrets and Keys
- Key Vault stores secrets, certificates, and keys
- Soft delete and purge protection enabled
- No long-lived secrets in Kubernetes manifests or images

### 7.3 PCI-DSS Controls
- TLS 1.2+ everywhere
- Encryption at rest for all services
- Centralized logging without sensitive data leakage
- Least privilege access and auditability

### 7.4 Monitoring and Logging
- AKS control plane and audit logs
- Application Gateway WAF logs
- Azure Firewall logs
- Key Vault diagnostics
- Redis diagnostics
- MySQL diagnostics
- Activity Logs and Entra ID logs
- All sent to Log Analytics

## 8. Availability and Resilience
To approach 99.99% in a single region:
- Zone-redundant Application Gateway WAF v2 where supported
- AKS node pools across Availability Zones 1, 2, and 3
- Multiple application replicas
- Pod Disruption Budgets
- Readiness and liveness probes
- Health-based routing and graceful shutdown
- Zone-redundant MySQL HA where available
- Redis Premium sized for resilience and throughput

## 9. Data Architecture
### 9.1 Redis
- Premium tier
- Private endpoint only
- Used for cache, session state, rate limiting, and idempotency keys
- Not the system of record

### 9.2 MySQL Flexible Server
- Private endpoint only
- Public access disabled
- Automated backups and point-in-time restore
- Zone-redundant HA if available in East US for the selected SKU

### 9.3 ACR and Key Vault
- Private endpoint only
- Public access disabled
- ACR used for private image pulls
- Key Vault used for secrets and certificates

## 10. Operational Controls
- IaC-only deployment preferred
- Azure Policy for enforcement
- Continuous compliance scanning
- WAF tuning and change control
- Incident response runbooks for WAF, credential compromise, private endpoint outage, database failover, and certificate expiration

## 11. Risks and Mitigations
- Single-region 99.99% is aggressive: mitigate with zone-aware design and testing
- Private-only PaaS increases DNS complexity: mitigate with standardized private DNS zones
- WAF false positives: mitigate with tuning and allowlists
- MySQL bottleneck risk: mitigate with caching, pooling, and query optimization
