# Technical Architecture Document (TAD)

## 1. Purpose
Design a highly secure, customer-facing web application on Azure Kubernetes Service (AKS) in East US with PCI-DSS-aligned encryption, strict network isolation, private-only PaaS connectivity, and 99.99% uptime objectives within a single region.

## 2. Scope
This document covers:
- Application ingress and compute on AKS
- Private connectivity to Azure Container Registry (ACR), Azure Key Vault, Azure Cache for Redis Premium, and Azure Database for MySQL Flexible Server
- Network segmentation and private DNS
- Security, compliance, logging, and operational controls
- FinOps budget baseline

## 3. Architecture Summary
### 3.1 Core Design
- **Ingress:** Azure Application Gateway WAF v2
- **Compute:** AKS private cluster with no public node IPs
- **Data/State:** Azure Cache for Redis Premium and Azure Database for MySQL Flexible Server
- **Secrets/Images:** Azure Key Vault and Azure Container Registry
- **Connectivity:** Private Endpoints only for all PaaS services
- **Region:** East US
- **Availability target:** 99.99% within a single region
- **Traffic target:** 10,000 requests per minute with autoscaling

### 3.2 Recommended Application Pattern
A **modular monolith + web-queue-worker** pattern is recommended:
- Web/API pods handle customer traffic
- Worker pods handle asynchronous processing
- Redis is used for cache/session/rate limiting
- MySQL is the system of record
- Key Vault stores secrets and certificates
- ACR stores container images

## 4. Logical Architecture
### 4.1 Request Flow
1. Customer traffic enters through **Application Gateway WAF v2**.
2. WAF inspects and forwards traffic to AKS ingress.
3. AKS services/pods process the request.
4. Pods access Redis, MySQL, Key Vault, and ACR through **Private Endpoints** only.
5. Logs and diagnostics are sent to Azure Monitor / Log Analytics.

### 4.2 Management Flow
- Administrative access is via **Azure Bastion** and/or an optional jump host with no public IP.
- AKS API access is private only.
- Entra ID, RBAC, MFA, and PIM are required for privileged access.

## 5. Network Architecture
### 5.1 Virtual Network and Subnets
A single VNet in East US should contain:
- `snet-appgw` for Application Gateway WAF v2
- `snet-aks-system` for AKS system node pool
- `snet-aks-user` for AKS user node pool
- `snet-private-endpoints` for all Private Endpoints
- `snet-bastion` for Azure Bastion
- `snet-jumpbox` optional admin VM subnet

### 5.2 Private DNS Zones
Link the following zones to the VNet:
- `privatelink.azurecr.io`
- `privatelink.vaultcore.azure.net`
- `privatelink.redis.cache.windows.net`
- `privatelink.mysql.database.azure.com`
- `privatelink.<region>.azmk8s.io`

### 5.3 Network Security Controls
- No public IPs on AKS nodes
- No public network access on ACR, Key Vault, Redis, or MySQL
- Kubernetes NetworkPolicies enabled
- Subnet-level NSGs and UDRs applied
- Egress restricted to approved destinations only
- Public ingress only through Application Gateway WAF v2

## 6. Compute Architecture
### 6.1 AKS
- Private cluster
- Azure CNI networking
- Separate system and user node pools
- Cluster autoscaler enabled
- Horizontal Pod Autoscaler enabled
- Pod Disruption Budgets configured
- Availability zone spread where supported in East US

### 6.2 Ingress
- Application Gateway WAF v2 is the sole public ingress point
- WAF policy in Prevention mode
- AGIC integration for AKS ingress
- TLS 1.2+ enforced

## 7. Data Architecture
### 7.1 Azure Cache for Redis Premium
- Private Endpoint only
- Public network access disabled
- TLS required
- Used for session state, hot data, and rate limiting

### 7.2 Azure Database for MySQL Flexible Server
- Private Endpoint only
- Public network access disabled
- TLS required
- System of record for transactional data
- Zone-redundant HA should be enabled if available in the selected tier/region configuration

### 7.3 Azure Key Vault
- Private Endpoint only
- Public network access disabled
- Stores secrets, certificates, and keys
- Managed identity access preferred
- Purge protection and soft delete enabled

### 7.4 Azure Container Registry
- Private Endpoint only
- Public network access disabled
- AKS image pulls occur over private connectivity only

## 8. Security and Compliance
### 8.1 PCI-DSS Controls
- TLS 1.2+ in transit
- Encryption at rest for all data services
- WAF inspection at ingress
- Private-only PaaS connectivity
- Least privilege access control
- MFA and PIM for administrative access
- Logging and monitoring enabled across all services

### 8.2 Identity and Access Management
- Microsoft Entra ID integration for AKS authentication
- Kubernetes RBAC plus Azure RBAC
- No shared admin accounts
- No long-lived cluster-admin assignments
- Break-glass accounts only, tightly controlled

### 8.3 Logging and Monitoring
Enable diagnostics for:
- AKS control plane logs
- Kubernetes audit logs
- Application Gateway WAF logs
- Container logs
- Azure Activity Logs
- Key Vault diagnostics
- Redis diagnostics
- MySQL diagnostics

Send logs to centralized Azure Monitor / Log Analytics and protect them from tampering.

## 9. Availability and Resilience
To support 99.99% uptime in a single region:
- Use zone-aware deployment where supported
- Run at least 2 replicas for critical workloads
- Use PDBs and rolling updates
- Enable autoscaling for App Gateway and AKS workloads
- Use Redis for transient state only
- Use MySQL connection pooling and retry logic

## 10. Operational Considerations
- Use managed identities for workload authentication
- Avoid storing secrets in code or container images
- Restrict egress with network policies and subnet controls
- Define secure break-glass and maintenance procedures
- Validate private DNS resolution for all private endpoints
- Confirm certificate handling for Application Gateway without relying on public Key Vault access

## 11. Key Architectural Decisions
| Area | Decision |
|---|---|
| Region | East US |
| Application style | Modular monolith with worker services |
| Ingress | Application Gateway WAF v2 |
| AKS exposure | Private cluster, no public node IPs |
| Cache | Azure Cache for Redis Premium |
| Database | Azure Database for MySQL Flexible Server |
| Secrets | Azure Key Vault |
| Images | Azure Container Registry |
| PaaS access | Private Endpoints only |
| Security model | PCI-DSS-aligned, least privilege, encrypted everywhere |

- It does **not** include:

  - Additional AKS node pools, autoscale headroom, or zone redundancy premiums

## 15. Conclusion
The architecture is feasible and aligned to the stated requirements if the following are treated as non-negotiable:
- Private AKS cluster
- No public node IPs
- Application Gateway WAF v2 as the only public ingress
- Private Endpoints only for ACR, Key Vault, Redis, and MySQL
- Entra ID + RBAC + PIM + MFA
- Centralized logging and monitoring
- Strict egress control and network segmentation
- PCI-focused encryption and key management
