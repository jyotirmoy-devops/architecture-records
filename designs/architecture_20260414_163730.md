## 1. Executive Summary
Design a highly secure, customer-facing web application on Azure Kubernetes Service (AKS) in East US with 10,000 requests per minute, auto-scaling, 99.99% uptime target in a single region, and PCI-DSS-aligned encryption. The application uses AKS for stateless workloads, Application Gateway WAF v2 as the only public ingress, Azure Cache for Redis Premium for caching/session acceleration, Azure Database for MySQL Flexible Server for transactional state, Azure Container Registry (ACR) for images, and Azure Key Vault for secrets, certificates, and encryption material.

All PaaS services must be reachable only through Private Endpoints with public network access disabled.

## 2. Scope and Design Goals
- Customer-facing web application
- Expected load: 10,000 requests/minute
- Auto-scaling required
- 99.99% uptime target in a single region (East US)
- PCI-DSS-aligned encryption standards
- AKS nodes must not have public IPs
- Ingress via Application Gateway WAF v2
- Azure Cache for Redis Premium and Azure Database for MySQL Flexible Server
- All PaaS services (ACR, Key Vault, Redis, MySQL) must have public network access entirely disabled and be connected exclusively via Private Endpoints

## 3. Target Azure Services
### Compute / Platform
- Azure Kubernetes Service (AKS)
  - Private cluster recommended
  - System and user node pools
  - Cluster autoscaler enabled
  - Horizontal Pod Autoscaler (HPA) enabled
- Application Gateway WAF v2
  - Internet-facing entry point
  - WAF policy in Prevention mode
  - AKS ingress via Application Gateway Ingress Controller (AGIC) or AGIC add-on

### Data / State
- Azure Cache for Redis Premium
  - Private Endpoint only
- Azure Database for MySQL Flexible Server
  - Private access only via Private Endpoint / private networking
- Azure Key Vault
  - Private Endpoint only
- Azure Container Registry (ACR)
  - Private Endpoint only

### Networking / Security
- Hub-spoke or single spoke VNet topology
- Private DNS Zones for all Private Endpoint-backed services
- Azure DDoS Network Protection recommended
- Azure Monitor + Log Analytics + Container Insights
- Microsoft Defender for Cloud recommended

## 4. Reference Architecture
Internet → Application Gateway WAF v2 → AKS Ingress → Kubernetes Services/Pods → Private PaaS services

AKS workloads access:
- ACR for image pulls
- Key Vault for secrets/certificates
- Redis for caching/session state
- MySQL for application data

All via Private Endpoints and Private DNS Zones.

## 5. Network Topology
A secure single-region design should use a dedicated VNet in East US with segmented subnets.

### Recommended VNet
- VNet: `vnet-prod-eastus`
- Address space: `10.10.0.0/16`

### Subnets
1. `snet-appgw`
   - For Application Gateway WAF v2
   - Example: `10.10.0.0/24`
2. `snet-aks-nodes`
   - AKS node pools
   - Example: `10.10.1.0/22`
3. `snet-aks-pods`
   - If using Azure CNI Overlay or delegated pod networking strategy, reserve accordingly
   - Example: `10.10.8.0/21`
4. `snet-private-endpoints`
   - Private Endpoints for ACR, Key Vault, Redis, MySQL
   - Example: `10.10.16.0/24`
5. `snet-bastion`
   - Optional Azure Bastion for admin access
   - Example: `10.10.17.0/26`

### Network Controls
- NSGs on all subnets
- UDRs if central inspection is required
- No public IPs on AKS nodes
- AKS API server private access strongly recommended
- Application Gateway is the only public ingress point
- Restrict outbound traffic from AKS using Azure Firewall or NVA if required, AKS egress control / UDRs, and explicit allow-listing for required Azure service endpoints and dependencies

## 6. Private DNS Zones Required
Create and link these Private DNS Zones to the VNet:
- `privatelink.azurecr.io`
- `privatelink.vaultcore.azure.net`
- `privatelink.redis.cache.windows.net`
- `privatelink.mysql.database.azure.com`

These zones ensure private name resolution for all private endpoints.

## 7. AKS Design
### Cluster Configuration
- Region: East US
- Cluster type: Private AKS cluster
- Node pools: At least 2 node pools
  - System node pool
  - User node pool
- Availability Zones: Use zone-redundant node pools if supported in East US for improved resiliency
- Autoscaling:
  - Cluster autoscaler enabled on node pools
  - HPA for application pods
- Network plugin: Azure CNI recommended for enterprise control
- Ingress: Application Gateway Ingress Controller / AGIC
- No public node IPs: enforced by design

### Recommended AKS Security Settings
- Azure AD integration / Entra ID RBAC
- Kubernetes RBAC least privilege
- Azure Policy for AKS
- Defender for Containers
- Secrets stored in Key Vault, not in Kubernetes secrets where possible
- Use managed identities for pod-to-Azure access

## 8. Application Gateway WAF v2 Design
### Role
- Public entry point for all customer traffic
- TLS termination and/or end-to-end TLS
- WAF protection against common web attacks

### Configuration
- SKU: WAF v2
- Mode: Prevention
- TLS: TLS 1.2+ only
- Certificates: Stored in Key Vault and referenced by App Gateway
- Backend: AKS ingress service
- Health probes: Custom probes for app readiness

### Security Recommendations
- Enable OWASP core rule set
- Add custom WAF rules for PCI-sensitive paths
- Restrict allowed methods and headers
- Use end-to-end encryption from App Gateway to AKS ingress if feasible

## 9. PaaS Private Endpoint Design
All listed PaaS services must have public network access disabled.

### Azure Container Registry
- Public network access: Disabled
- Private Endpoint: Yes
- Use: AKS image pulls only via private DNS

### Azure Key Vault
- Public network access: Disabled
- Private Endpoint: Yes
- Use: TLS certs, secrets, encryption keys, app secrets

### Azure Cache for Redis Premium
- Public network access: Disabled
- Private Endpoint: Yes
- Use: Session state, caching, rate limiting, distributed locks

### Azure Database for MySQL Flexible Server
- Public network access: Disabled
- Private Endpoint: Yes
- Use: Application relational data store

## 10. Data Protection / PCI-DSS Alignment
### Encryption in Transit
- TLS 1.2+ everywhere
- HTTPS from client to App Gateway
- TLS from App Gateway to AKS ingress/backend
- TLS from AKS to Redis/MySQL/Key Vault/ACR

### Encryption at Rest
- Azure-managed encryption by default
- For stronger PCI posture:
  - Use customer-managed keys where supported
  - Store keys in Key Vault
- MySQL Transparent Data Encryption is enabled by platform
- Redis Premium encryption at rest supported by service capabilities

### Secrets Management
- Use Key Vault for:
  - DB credentials if not using managed auth
  - TLS certificates
  - Application secrets
- Prefer Managed Identities for AKS workloads
- Use CSI Secrets Store Driver for Key Vault integration

### PCI-DSS Controls
- Network segmentation
- Least privilege access
- Centralized logging and audit trails
- WAF protection
- Strong key management
- No public exposure of data services

## 11. Availability and Scaling
### Availability Target
- 99.99% in a single region is achievable only with careful design and service selection.

### Resiliency Measures
- Application Gateway WAF v2 is zone-redundant where supported
- AKS node pools spread across availability zones
- Multiple replicas for app pods
- Pod disruption budgets
- Readiness/liveness probes
- Redis and MySQL configured for high availability options where available

### Scaling
- 10,000 requests/minute is moderate for AKS with proper autoscaling
- Use HPA based on CPU/memory and/or custom metrics
- Cluster autoscaler for node growth
- App Gateway autoscaling
- Ensure backend pod count and node capacity can absorb traffic spikes

## 12. Identity and Access
- Microsoft Entra ID for human access
- Managed Identities for Azure resource access
- Role-based access control:
  - Separate platform admin, app operator, and security admin roles
- No shared credentials
- Just-in-time access for administrative operations if using Bastion/VM jump access

## 13. Logging, Monitoring, and Security Operations
### Monitoring
- Azure Monitor
- Log Analytics Workspace
- Container Insights
- Application Insights for app telemetry

### Security Monitoring
- Microsoft Defender for Cloud
- WAF logs to Log Analytics / Sentinel
- AKS audit logs
- Key Vault diagnostic logs
- MySQL audit/slow query logs
- Redis diagnostics where supported

### Alerting
- Pod crash loops
- Node pressure
- WAF blocks/spikes
- Private Endpoint connectivity failures
- MySQL CPU/storage/connection saturation
- Redis memory pressure
- Certificate expiration

## 14. Recommended Deployment Pattern
### Minimum Production Layout
- 1 x Application Gateway WAF v2
- 1 x Private AKS cluster
- 2+ node pools
- 1 x ACR with private endpoint
- 1 x Key Vault with private endpoint
- 1 x Redis Premium with private endpoint
- 1 x MySQL Flexible Server with private endpoint
- 1 x Log Analytics Workspace
- 1 x Azure Monitor / App Insights
- 1 x VNet with dedicated subnets
- 4 x Private DNS Zones

## 15. Key Design Decisions
1. Application Gateway WAF v2 is the only public ingress.
2. AKS is private and nodes have no public IPs.
3. All PaaS services are private-only with public access disabled.
4. Private DNS Zones are mandatory for service resolution.
5. Managed identities + Key Vault reduce secret exposure.
6. Zone-redundant, autoscaled design supports the 99.99% target in-region.
7. WAF + encryption + segmentation align with PCI-DSS expectations.

## 16. Risks and Considerations
- Single-region 99.99% is strong but not equivalent to geo-redundant DR.
- MySQL Flexible Server private access must be validated against the exact networking mode chosen; ensure the deployment model supports private-only connectivity as required.
- Application Gateway and AKS ingress integration must be tested for certificate handling and health probe behavior.
- Private Endpoint DNS misconfiguration is a common failure point; automate zone linking and record validation.
- Egress control may require Azure Firewall if the application has external dependencies.

## 17. Final Recommended Physical Architecture
East US
- Public subnet: Application Gateway WAF v2
- Private AKS cluster in dedicated subnets
- Private Endpoints subnet for:
  - ACR
  - Key Vault
  - Redis Premium
  - MySQL Flexible Server
- Private DNS Zones linked to the VNet
- Monitoring and security services enabled
- No public IPs on AKS nodes
- No public access on any PaaS service

## 19. Conclusion
This architecture satisfies the stated requirements by combining a private AKS cluster, WAF-protected ingress, private-only PaaS connectivity, PCI-DSS-aligned encryption, and autoscaling for the expected traffic profile. The design is conditionally suitable for a single-region 99.99% target, subject to final validation of zone support, service SLAs, and operational controls.
