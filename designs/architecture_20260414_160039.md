# 1. Executive Summary
Design a highly secure, customer-facing web application on Azure Kubernetes Service (AKS) in East US with autoscaling for 10,000 requests per minute, 99.99% uptime target in a single region, PCI-DSS-aligned encryption, no public IPs on AKS nodes, and ingress only through Application Gateway WAF v2. All PaaS services (ACR, Key Vault, Redis, MySQL) must have public network access disabled and use Private Endpoints exclusively.

# 2. Architecture Overview
- **Region:** East US
- **Ingress:** Application Gateway WAF v2
- **Compute:** Private AKS cluster with no public node IPs
- **Data/State:** Azure Cache for Redis Premium, Azure Database for MySQL Flexible Server
- **Secrets/Images:** Azure Key Vault, Azure Container Registry Premium
- **Connectivity:** Private Endpoints only for all PaaS services
- **Observability:** Azure Monitor / Log Analytics

# 3. Key Design Principles
1. Zero Trust by default
2. Private-by-design for all PaaS access
3. Least privilege with managed identities
4. Defense in depth with WAF, network controls, encryption, and logging
5. Immutable and auditable operations via IaC and policy-as-code

# 4. Logical Architecture
## 4.1 Request Flow
1. Customer traffic enters **Application Gateway WAF v2**.
2. WAF inspects and forwards traffic to **AKS ingress**.
3. AKS services process requests and access:
   - **Redis** for caching/session acceleration
   - **MySQL** for transactional persistence
   - **Key Vault** for secrets/certificates/keys
   - **ACR** for image pulls
4. Logs and metrics are sent to **Log Analytics / Azure Monitor**.

## 4.2 Application Pattern
- Stateless web/API services on AKS
- Horizontal Pod Autoscaler for pod scaling
- Cluster Autoscaler for node scaling
- Cache-aside pattern with Redis
- MySQL as system of record
- Async worker pattern for long-running tasks

# 5. Network Architecture
## 5.1 Hub-Spoke Topology
- **Hub VNet**
  - Application Gateway WAF v2 subnet
  - Optional shared services / DNS / management
- **Spoke VNet**
  - AKS node subnets
  - Private Endpoint subnet(s)
  - Optional management subnet

## 5.2 Network Controls
- No public IPs on AKS nodes
- No public access to ACR, Key Vault, Redis, or MySQL
- Private DNS zones required for all Private Link services
- NSGs and UDRs to enforce deny-by-default posture

## 5.3 Private DNS Zones
- `privatelink.azurecr.io`
- `privatelink.vaultcore.azure.net`
- `privatelink.redis.cache.windows.net`
- `privatelink.mysql.database.azure.com`

# 6. Security Architecture
## 6.1 Identity and Access
- Microsoft Entra ID for human access
- Managed Identities / Workload Identity for workloads
- MFA for privileged users
- PIM for just-in-time elevation
- No shared admin accounts
- Break-glass accounts only with strict governance

## 6.2 Encryption
- TLS 1.2+ everywhere
- WAF terminates or passes through TLS based on certificate strategy
- Encryption at rest for all data stores
- Key Vault for secrets, certificates, and keys
- CMK where supported and required by policy

## 6.3 Logging and Monitoring
- AKS control plane logs
- Kubernetes audit logs
- Application logs
- WAF logs
- Azure Activity Logs
- Key Vault diagnostics
- ACR diagnostics
- Redis diagnostics
- MySQL audit and slow query logs
- Azure Policy compliance logs
- Defender for Cloud alerts

# 7. Availability and Resilience
- Zone-aware AKS node pools where supported
- Multiple replicas for critical services
- Pod disruption budgets
- Readiness and liveness probes
- Zone-redundant Application Gateway where available
- MySQL HA where supported
- Redis Premium redundancy features where applicable
- Backup and restore testing

# 8. Compliance Considerations
- PCI-DSS encryption in transit and at rest
- Strong access control and least privilege
- Network segmentation and restricted inbound/outbound paths
- Centralized logging and audit retention
- Vulnerability management and patch governance
- Policy enforcement and drift detection

# 9. Operational Guardrails
- Infrastructure as Code mandatory
- Policy-as-code mandatory
- Change approvals for network, identity, and key management changes
- Security architecture review before production
- Periodic access recertification
- Penetration testing and vulnerability scanning
- Incident response runbooks for WAF, AKS, Key Vault, Redis, and MySQL

# 11. Final Recommendation
Approve the solution only if:
- AKS has no public node IPs
- All PaaS services are private-endpoint only with public access disabled
- Application Gateway WAF v2 is the sole internet ingress
- Managed identities and least privilege are enforced
- Centralized logging, alerting, and audit retention are implemented
- Encryption in transit and at rest is enforced with strong key governance
- Network segmentation and private DNS are treated as mandatory controls
