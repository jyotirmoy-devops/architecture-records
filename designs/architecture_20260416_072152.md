# 1. Executive Summary
This architecture supports a new customer-facing online storefront for a clothing brand. It is designed to provide reliable product browsing and secure storage for inventory, customer accounts, and order history.

The recommended solution is a secure Azure PaaS-first design centered on:
- Azure App Service for the storefront and API layer
- Azure SQL Database for transactional data
- Azure Key Vault for secrets and keys
- Application Gateway WAF v2 for internet ingress protection
- Private Endpoints and Private DNS Zones for private service access
- Microsoft Entra ID for identity
- Azure Monitor, Application Insights, and Log Analytics for observability

The original requirement has been adjusted to reflect the expert reports because they introduce necessary enterprise controls for security, compliance, logging, encryption, and network isolation. These controls are required for a production-grade customer-facing storefront and take precedence over the simpler baseline requirement.

# 4. Logical Application Architecture
The application should be implemented as a modular monolith or domain-oriented architecture initially, with clear boundaries for:
- Catalog domain
- Customer domain
- Inventory domain
- Order domain
- Fulfillment domain
- Notification domain

Recommended patterns:
- Domain-Driven Design
- CQRS for browse vs transactional workloads
- Event-driven processing for order and inventory workflows
- Web-queue-worker pattern for asynchronous tasks
- Outbox pattern for reliable event publication
- Saga/process manager for checkout orchestration

## Core request flows
### Browse products
Customer browser -> Catalog API -> cached or database-backed product data

### Sign in / account access
Customer browser -> Authentication layer -> customer profile and account services

### Place order
Customer browser -> Order API -> order creation -> inventory reservation -> confirmation -> notification

### View order history
Customer browser -> Order History API -> customer-specific order records

# 5. Azure Infrastructure Architecture
## Recommended services
- Azure Application Gateway v2 with WAF
- Azure App Service
- Azure SQL Database
- Azure Key Vault
- Azure Cache for Redis
- Azure Blob Storage
- Microsoft Entra ID
- Azure Monitor
- Application Insights
- Log Analytics Workspace
- Private Endpoints
- Private DNS Zones
- Azure Firewall optional for outbound governance

## Physical flow
Internet -> Application Gateway (WAF) -> App Service -> Azure SQL Database

App Service uses VNet integration and private endpoints to reach SQL, Key Vault, Redis, and Blob Storage privately.

## Network topology
A production VNet should include:
- App Service integration subnet
- Application Gateway subnet
- Private endpoint subnet
- Optional management subnet

Private DNS zones should be linked for:
- privatelink.database.windows.net
- privatelink.vaultcore.azure.net
- privatelink.redis.cache.windows.net if used
- privatelink.blob.core.windows.net

## Security controls
- No public SQL endpoint
- No public Key Vault endpoint
- No direct database access from the internet
- WAF in front of the storefront
- TLS 1.2+ in transit
- Managed identities for service-to-service access
- NSGs and egress restrictions where required

# 6. Data Architecture
## Primary transactional store
Azure SQL Database is the system of record for:
- Customers
- CustomerAddresses
- Products
- ProductVariants
- Inventory
- InventoryTransactions
- Orders
- OrderItems
- Payments metadata
- Shipments
- Returns

## Cache
Azure Cache for Redis is used for:
- Session state
- Cart state
- Product hot cache
- Rate limiting support

## Object storage
Azure Blob Storage is used for:
- Product images
- Marketing assets
- Invoices and receipts
- Exports
- Archive files

## Data protection
- Encryption at rest enabled for all stores
- Customer-managed keys via Key Vault where required
- Private endpoints for SQL, Storage, Redis, and Key Vault
- Managed identities for application access
- Sensitive data minimized and separated where possible

# 7. Security, Compliance, and Governance
## IAM requirements
- Centralized identity provider for workforce/admin access
- MFA for privileged users
- Least privilege RBAC
- No shared accounts
- Privileged access approval workflow
- Separate customer identity domain from workforce identity
- Managed identities for non-human access
- Secrets rotation and no hardcoded credentials

## Logging and audit requirements
- Centralized log collection
- Audit logs for privileged actions
- Customer account event logging
- Database access logging
- Administrative console access logging
- Tamper-resistant log storage
- Time synchronization
- Alerts for suspicious activity

## Encryption requirements
- TLS 1.2+ in transit
- Encryption at rest for all sensitive data
- Centralized key management via KMS/HSM-backed service
- Key rotation policy
- Separation of duties for key administration
- No plaintext secrets in code or CI/CD

## Network isolation requirements
- Public exposure only for the web tier
- Application and data tiers private
- Segmentation between customer-facing and back-office systems
- Egress controls
- WAF and DDoS protection
- Environment separation for dev, test, staging, and production

## Compliance considerations
Potentially applicable frameworks and laws:
- GDPR / UK GDPR
- CCPA/CPRA
- NIST CSF
- NIST 800-53
- CIS Controls
- PCI DSS if payment data is processed

# 8. Availability and Resilience
## App Service
- Standard or higher tier
- Autoscale enabled
- 3 or more instances for high availability where needed

## SQL Database
- Business Critical tier recommended
- Zone redundancy in primary region
- Auto-failover groups to paired secondary region
- Automated backups and point-in-time restore

## Redis
- Treat as rebuildable cache
- Use geo-replication only if required by DR objectives

## Blob Storage
- ZRS or GRS depending on resilience needs
- Soft delete and versioning for critical containers

## Target RTO/RPO
- Storefront: RTO 5–15 minutes, RPO near-zero to 5 minutes
- Transactional order processing: RTO under 1 minute, RPO 0 to near-zero
- Cache: minutes, rebuildable
- Blob assets: 15–60 minutes depending on failover mode

# 12. Final Recommendation
The best starting architecture is:
- Azure App Service
- Azure SQL Database
- Azure Key Vault
- Application Gateway WAF
- Private Endpoints
- Microsoft Entra ID
- Azure Monitor and Application Insights

This design is secure, reliable, and cost-effective for launch, while leaving room to add Cosmos DB, Redis, Front Door, or additional governance controls later as the storefront grows.
