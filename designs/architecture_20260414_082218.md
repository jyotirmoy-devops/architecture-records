# Technical Architecture Document

## 1. Executive Summary

This document defines a secure, customer-facing web application architecture on **Azure Kubernetes Service (AKS)** in **East US**. The solution is designed for:

- **10,000 requests per minute**
- **Auto-scaling**
- **99.99% uptime target in a single region**
- **PCI-DSS encryption standards**
- **No public IPs on AKS nodes**
- **Application Gateway WAF v2** as the only internet-facing ingress
- **Private Endpoint-only access** for all PaaS services

The architecture uses **AKS**, **Application Gateway WAF v2**, **Azure Cache for Redis Premium**, **Azure Database for MySQL Flexible Server**, **Azure Container Registry (ACR)**, and **Azure Key Vault**. All PaaS services have **public network access disabled** and are reachable **exclusively via Private Endpoints**.

## 2. Architecture Overview

### 2.1 Logical Pattern
The application follows a **stateless web application pattern** with:

- **Public ingress** through Application Gateway WAF v2
- **Private AKS cluster** for application workloads
- **Redis** for caching and session acceleration
- **MySQL Flexible Server** for transactional persistence
- **Key Vault** for secrets, certificates, and keys
- **ACR** for private container image distribution
- **Private DNS Zones** for name resolution of private endpoints
- **Azure Firewall** for controlled egress

### 2.2 High-Level Traffic Flow
1. Internet user connects to **Application Gateway WAF v2**.
2. WAF inspects and forwards HTTPS traffic to AKS privately.
3. AKS application pods process the request.
4. Application accesses:
   - **Redis** via Private Endpoint
   - **MySQL** via Private Endpoint
   - **Key Vault** via Private Endpoint
   - **ACR** for image pulls via Private Endpoint
5. Logs are forwarded to centralized monitoring/SIEM.

## 3. Requirements Traceability

| Requirement | Architecture Response |
|---|---|
| 10,000 requests/minute | AKS HPA + Cluster Autoscaler; App Gateway autoscaling; Redis caching |
| 99.99% uptime in single region | East US multi-zone deployment, zone-redundant components where supported |
| PCI-DSS encryption | TLS 1.2+ end-to-end, encryption at rest, Key Vault-backed secrets/certs |
| AKS nodes must not have public IPs | Private AKS cluster / private node pools with no public IPs |
| Ingress via Application Gateway WAF v2 | App Gateway is the only public entry point |
| Redis and MySQL required | Redis Premium and MySQL Flexible Server with private access only |
| All PaaS private-only | Public network access disabled; Private Endpoints only for ACR, Key Vault, Redis, MySQL |

## 4. Target Azure Services

### 4.1 Compute and Ingress
- **Azure Kubernetes Service (AKS)**
  - Private cluster
  - No public node IPs
  - Cluster autoscaler enabled
  - Horizontal Pod Autoscaler enabled
  - Multi-zone node placement in East US where supported

- **Application Gateway WAF v2**
  - Public frontend IP
  - WAF enabled in prevention mode
  - TLS termination and/or re-encryption
  - Zone-redundant deployment where supported

### 4.2 Data and State
- **Azure Cache for Redis Premium**
  - Private Endpoint only
  - Public network access disabled
  - Used for caching, session state, and rate limiting

- **Azure Database for MySQL Flexible Server**
  - Private Endpoint only
  - Public network access disabled
  - Primary transactional data store
  - Automated backups enabled
  - Zone-redundant HA if supported by selected SKU/region

### 4.3 Security and Supply Chain
- **Azure Key Vault**
  - Private Endpoint only
  - Public network access disabled
  - Stores secrets, certificates, and keys
  - Soft delete and purge protection enabled

- **Azure Container Registry (ACR)**
  - Private Endpoint only
  - Public network access disabled
  - Used for private image pulls by AKS

### 4.4 Network and Monitoring
- **Private DNS Zones**
  - Required for private endpoint resolution
- **Azure Firewall**
  - Controlled outbound egress
- **Log Analytics / SIEM**
  - Centralized logging and alerting

## 5. Network Topology

### 5.1 Hub-Spoke Layout
A hub-spoke model is recommended in East US.

#### Hub VNet
Contains shared services:
- Azure Firewall
- Optional DNS resolver components
- Optional bastion/jump access for operations

#### Spoke VNet
Contains application workload components:
- Application Gateway subnet
- AKS node subnet(s)
- Private Endpoint subnet(s)
- Optional management subnet

### 5.2 Subnet Segmentation
- **AppGatewaySubnet**: dedicated to Application Gateway WAF v2
- **AKS-NodeSubnet**: AKS node pools, no public IPs
- **PrivateEndpointSubnet**: private endpoints for ACR, Key Vault, Redis, MySQL
- **AzureFirewallSubnet**: Azure Firewall in hub VNet

### 5.3 Private DNS Zones
The following private DNS zones are required:
- `privatelink.azurecr.io`
- `privatelink.vaultcore.azure.net`
- `privatelink.redis.cache.windows.net`
- `privatelink.mysql.database.azure.com`

## 6. Security Architecture

### 6.1 Ingress Security
- Only **Application Gateway WAF v2** is internet-facing.
- WAF runs in **prevention mode**.
- TLS 1.2+ is enforced.
- Strong cipher suites are required.
- HTTP is redirected to HTTPS.

### 6.2 AKS Security
- AKS is deployed as a **private cluster**.
- Nodes have **no public IPs**.
- Kubernetes RBAC and Entra ID integration are required.
- Network policies should be enabled.
- Workloads should use managed identity / workload identity.

### 6.3 PaaS Security
All PaaS services must have:
- **Public network access disabled**
- **Private Endpoint only connectivity**
- **Private DNS integration enabled**

This applies to:
- ACR
- Key Vault
- Redis
- MySQL Flexible Server

### 6.4 Egress Security
- AKS outbound traffic is forced through **Azure Firewall**.
- Default deny outbound posture is recommended.
- Only approved Azure and business-required destinations are allowed.

## 7. Availability and Resilience

### 7.1 99.99% Target
To approach 99.99% uptime in a single region:
- Deploy across **Availability Zones** in East US.
- Use zone-redundant Application Gateway where supported.
- Spread AKS node pools across zones.
- Use MySQL HA options where available.
- Use multiple application replicas.
- Configure health probes, autoscaling, and pod disruption budgets.

### 7.2 Resilience Controls
- Readiness and liveness probes
- Retry with backoff and jitter
- Circuit breakers for downstream dependencies
- Idempotent request handling
- Graceful degradation if Redis is unavailable

## 8. Application and Data Design

### 8.1 Application Pattern
Recommended pattern:
- **Stateless web/API services** on AKS
- **Redis** for cache/session acceleration
- **MySQL** as system of record
- Optional background workers for asynchronous tasks

### 8.2 Data Partitioning
- **MySQL**: durable transactional data
- **Redis**: ephemeral cache, session state, rate limiting
- **Key Vault**: secrets, certificates, keys
- **ACR**: container images

### 8.3 Encryption
- TLS 1.2+ in transit
- Encryption at rest for all data services
- Customer-managed keys where required by policy
- Secrets and certificates stored only in Key Vault

## 9. Logging and Monitoring

Enable diagnostic logging for:
- Application Gateway WAF v2
- AKS control plane and audit logs
- Key Vault access logs
- MySQL audit and slow query logs
- Redis diagnostics
- ACR login and repository events
- Azure Activity Logs
- Azure Firewall logs

Forward logs to a centralized SIEM / Log Analytics workspace with retention and alerting.

## 10. Governance and Compliance

### 10.1 PCI-DSS Alignment
- TLS everywhere
- Encryption at rest
- Least privilege access
- Private-only PaaS connectivity
- Centralized logging
- Secret rotation and certificate lifecycle management
- Segmentation of the cardholder data environment

### 10.2 Identity and Access
- Entra ID for human and workload identities
- MFA for privileged users
- PIM for just-in-time elevation
- No shared accounts
- Quarterly access reviews

## 11. Operational Considerations

- Use Infrastructure as Code for all resources.
- Validate private DNS resolution during deployment.
- Test failover and restore procedures regularly.
- Monitor WAF false positives and tune rules carefully.
- Ensure AKS image pulls use managed identity and private ACR access.
- Document any external egress exceptions.

## 12. Risks and Mitigations

### Risk: Single-region 99.99% availability is difficult to guarantee
- **Mitigation:** Use zone redundancy, autoscaling, and operational controls; accept residual regional risk.

### Risk: Private Endpoint DNS misconfiguration
- **Mitigation:** Standardize private DNS zones and manage them via IaC.

### Risk: Redis or MySQL bottlenecks under load
- **Mitigation:** Use caching, connection pooling, query optimization, and scaling controls.

### Risk: WAF false positives
- **Mitigation:** Start with logging/tuning, then move to prevention mode.

## 13. Final Architecture Summary

**Internet** → **Application Gateway WAF v2** → **AKS private cluster** → **Private Endpoints** → **Redis / MySQL / Key Vault / ACR**

Supporting controls:
- Azure Firewall
- Private DNS Zones
- NSGs / route controls
- Azure Policy
- Defender for Cloud
- Log Analytics / SIEM
